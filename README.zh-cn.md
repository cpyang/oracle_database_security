## 概述

> **范围：** 本指南仅关注**本地部署的 Oracle 数据库**，支持 **Oracle 11gR2** 和 **Oracle 19c**。

保护敏感数据是任何组织的关键需求。Oracle 提供了多种加密策略，每种策略在透明度、性能、粒度和操作复杂度方面各有不同的权衡。

本指南帮助您：

- **了解** Oracle 生态系统中可用的加密方法
- **选择** 适合您用例的正确加密策略
- **实现** 加密功能，提供实用的测试示例
- **应用** 标签安全和数据脱敏实现细粒度访问控制

### 加密方案

| 方案 | 描述 | 透明度 | 粒度 |
|----------|-------------|-------------|-------------|
| **TDE** | Oracle 透明数据加密 —— 加密静态数据 | 对应用程序完全透明 | 列级或表空间级 |
| **应用层** | 应用程序代码处理加密/解密 | 应用程序控制 | 行级、列级或字段级 |
| **标签安全** | Oracle 标签安全（OLS）—— 基于敏感性的行级访问控制 | 数据库级策略执行 | 带敏感性标签的行级 |
| **数据脱敏** | Oracle 数据脱敏 —— 在查询时屏蔽敏感数据 | 对应用程序透明 | 带屏蔽策略的列级 |

## 加密方案对比

### 1. Oracle 透明数据加密（TDE）

TDE 加密**静态**数据 —— 包括数据文件、重做日志和备份文件 —— 无需更改应用程序代码。

#### 关键特性

- **列级 TDE**：加密包含敏感数据的单个列（例如，身份证号、信用卡号、医疗记录）
- **表空间级 TDE**：自动加密表空间中的所有数据
- **基于钱包的密钥管理**：使用外部钱包（硬件安全模块或软件钱包）保护加密密钥
- **零应用程序更改**：应用程序照常查询和插入数据

#### 何时使用 TDE

- 合规性要求规定加密静态数据
- 希望在不修改应用程序代码的情况下实现加密
- 保护物理数据被盗（磁盘被盗、备份泄露）
- 加密大量结构化数据

#### 限制

- 数据在内存中解密 —— 对任何拥有数据库访问权限的人可见
- 没有基于用户或基于会话的加密
- 无法基于上下文因素（时间、用户角色等）进行加密
- 仅限于结构化列数据

---

### 2. 应用层加密

应用程序代码在数据接触数据库之前显式加密和解密数据。

#### 关键特性

- **完全控制** 加密算法、密钥管理和数据处理
- **细粒度加密** —— 加密特定字段、行或部分文本
- **上下文感知** —— 加密决策可以基于用户角色、时间、位置等
- **多租户隔离** —— 不同租户可以使用不同的密钥

#### 何时使用应用层加密

- 需要租户隔离加密的多租户应用程序
- 加密密钥分离的监管要求
- 需要字段级或部分加密（例如，仅加密姓名的一部分）
- 在 TDE 密钥不同的多个数据库/租户之间共享数据
- 零信任架构，即使是数据库管理员也无法访问明文
- 需要基于上下文加密（基于用户、时间等）

#### 限制

- 需要更改应用程序代码
- 查询和索引变得复杂（没有特殊技术无法直接对加密数据进行 `WHERE` 查询）
- 应用层性能开销
- 必须构建和维护密钥管理

---

### 3. Oracle 标签安全（OLS）

Oracle 标签安全提供基于分配给数据和用户的敏感性标签的**行级**访问控制。

#### 关键特性

- **基于标签的访问控制**：每行和用户会话都分配一个标签
- **细粒度控制**：基于保密性和完整性组件控制访问
- **策略执行**：数据库自动强制执行基于标签的访问
- **分层标签**：支持层次结构和基于组件的标签

#### 何时使用标签安全

- 需要基于数据敏感性的行级访问控制
- 多级安全环境（例如，机密、秘密、绝密）
- 基于标签数据保护的合规性要求
- 需要基于用户权限的动态访问控制的应用程序

#### 限制

- 需要应用程序与 OLS API 集成
- 标签评估的性能开销
- 复杂策略管理
- 额外许可（高级安全选项）

---

### 4. Oracle 数据脱敏

Oracle 数据脱敏在查询时**屏蔽敏感数据**，而不修改底层数据。

#### 关键特性

- **实时脱敏**：查询时即时脱敏数据
- **完全和部分脱敏**：屏蔽整个值或特定部分
- **基于模式的脱敏**：自动检测和屏蔽模式（例如，信用卡号）
- **正则表达式脱敏**：特定数据格式的自定义模式
- **无需应用程序更改**：与现有应用程序透明工作

#### 何时使用数据脱敏

- 需要为特定用户或角色屏蔽敏感数据
- 数据屏蔽的合规性要求（例如，GDPR、HIPAA）
- 测试和开发环境需要类生产数据
- 防止应用程序日志或错误消息中的数据泄露
- 基于用户上下文的动态屏蔽

#### 限制

- 数据仍以明文形式存储在数据库中
- 不能防止物理数据被盗
- 脱敏策略必须精心设计和维护
- 脱敏评估的性能开销

## 决策框架

使用以下决策树选择正确的加密方法：

```
数据是否敏感（个人身份信息、财务、健康等）？
├── 否  → 不需要加密（或考虑一般数据保护）
└── 是
    │
    ├── 是否需要保护静态数据（磁盘、备份）？
    │   ├── 是 → 使用 TDE（列级或表空间级）
    │   └── 否  → 继续
    │
    ├── 是否需要为特定用户/角色在查询时屏蔽数据？
    │   ├── 是 → 使用数据脱敏
    │   └── 否  → 继续
    │
    ├── 不同用户/租户是否需要不同的加密密钥？
    │   ├── 是 → 使用应用层加密
    │   └── 否  → 继续
    │
    ├── 是否需要基于敏感性标签的行级访问控制？
    │   ├── 是 → 使用 Oracle 标签安全
    │   └── 否  → 继续
    │
    ├── 数据库管理员是否需要访问明文？
    │   ├── 否  → 使用应用层加密（密钥在数据库外部）
    │   └── 是 → 继续
    │
    ├── 是否需要上下文感知加密（基于用户、时间等）？
    │   ├── 是 → 使用应用层加密
    │   └── 否 → 使用 TDE
    │
    └── 是否在构建微服务/无服务器架构？
        ├── 是 → 考虑外部加密服务
        └── 否 → 根据需要使用 TDE + 应用层加密
```

### 快速决策矩阵

| 需求 | 推荐方案 |
|-------------|---------------------|
| 加密静态数据，零应用程序更改 | **TDE** |
| 防止磁盘/备份被盗 | **TDE** |
| 为特定用户/角色屏蔽数据 | **数据脱敏** |
| 多租户密钥隔离 | **应用层加密** |
| 即使是数据库管理员也无法读取数据 | **应用层加密** |
| 使用自定义逻辑加密特定字段 | **应用层加密** |
| 基于敏感性进行行级访问控制 | **标签安全** |
| 查询时动态数据屏蔽 | **数据脱敏** |
| 合规性 —— 要求加密静态数据 | **TDE**（最低要求） |
| 最大安全性 + 透明度 | **TDE + 应用层加密 + 脱敏**（纵深防御） |

## 许可概述

> **重要提示：** Oracle 许可可能很复杂。始终应与您的 Oracle 合同和许可专家核实。以下是一般性指南。

### Oracle 数据库版本

| 版本 | TDE | 标签安全 | 数据脱敏 | DBMS_CRYPTO |
|---------|-----|----------------|----------------|-------------|
| **标准版一 (SE1)** | ❌ 不可用 | ❌ 不可用 | ❌ 不可用 | ✅ 可用 |
| **标准版 (SE)** | ❌ 不可用 | ❌ 不可用 | ❌ 不可用 | ✅ 可用 |
| **企业版 (EE)** | ✅ 需要高级安全选项 | ✅ 需要高级安全选项 | ✅ 需要高级安全选项 | ✅ 可用 |

### 高级安全选项（ASO）

**高级安全选项** 是以下功能所需的额外许可：

- **TDE**（透明数据加密）—— 列加密和表空间加密
- **Oracle 标签安全（OLS）**
- **Oracle 数据脱敏**
- **高级审计功能**
- **强加密算法**（AES-256 等）

**许可模式：**
- 按**处理器**或按**用户**（命名用户Plus）出售
- 必须为集群中的所有处理器/核心许可（RAC 环境）
- 最低许可：每处理器 4 个命名用户 Plus

### Oracle 密钥管理器（OKM）许可

| 组件 | 许可要求 | 备注 |
|-----------|-------------------|-------|
| **Oracle 密钥管理器** | 企业版 + 高级安全选项 | OKM 服务器必需 |
| **OKM 客户端** | 涵盖数据库许可 | 连接到 OKM 的 TDE 客户端无需额外许可 |

### 第三方工具许可

| 工具 | 许可类型 | 费用 |
|------|-------------|------|
| **HashiCorp Vault** | BSL（源代码可用许可证） | 社区版免费；企业版需要订阅 |
| **Thales HSM** | 硬件购买 + 支持合同 | 商业产品 |
| **Utimaco HSM** | 硬件购买 + 支持合同 | 商业产品 |
| **Kong API Gateway** | 开源（Apache 2.0）+ 企业版 | 社区版免费；企业版需要订阅 |

### 总结：各功能的许可要求

| 功能 | 数据库版本 | 额外许可 | 密钥管理成本 |
|---------|-----------------|---------------------|---------------------|
| **TDE** | 企业版 | 高级安全选项 | HSM（硬件成本）或 OKM（包含在 ASO 中）或软件钱包（免费） |
| **应用层** | 任意版本 | 无 | HashiCorp Vault（免费）或 HSM（硬件成本） |
| **标签安全** | 企业版 | 高级安全选项 | 无（内置） |
| **数据脱敏** | 企业版 | 高级安全选项 | 无（内置） |
| **DBMS_CRYPTO** | 任意版本 | 无 | 无（内置包） |

### 涵盖主题

| 主题 | 文件 | 描述 |
|-------|------|-------------|
| Python 加密 | `samples/python/` | 使用 cryptography 库的 Python 示例 |
| Java 加密 | `samples/java/` | 使用 javax.crypto 的 Java 示例 |
| Node.js 加密 | `samples/nodejs/` | 使用 crypto 模块的 Node.js 示例 |
| 密钥管理 | `samples/key-management/` | 安全密钥处理模式 |

### 快速 Python 示例

```python
from cryptography.fernet import Fernet
import os

# 生成并安全存储密钥（切勿硬编码！）
key = Fernet.generate_key()
cipher = Fernet(key)

# 在存储之前加密数据
plaintext = b"敏感客户数据"
ciphertext = cipher.encrypt(plaintext)

# 需要时解密
plaintext = cipher.decrypt(ciphertext)
```

有关包括 Oracle 数据库集成在内的完整示例，请参阅 `samples/python/`。

### 快速 TDE 设置

```sql
-- 1. 在 sqlnet.ora 中设置钱包位置
ENCRYPTION_WALLET_LOCATION=(
  SOURCE=(METHOD=OKV)(METHOD_DATA=(
    (OKV_SERVER=your-key-server)(OKV_PORT=1521)))

-- 2. 打开钱包
ALTER SYSTEM SET WALLET OPEN IDENTIFIED BY "your-wallet-password";

-- 3. 创建 TDE 主密钥
ALTER SYSTEM SET ENCRYPTION KEY IDENTIFIED BY "your-wallet-password";

-- 4. 加密列
ALTER TABLE customers MODIFY (ssn ENCRYPT);
```

```sql

    object_schema   => 'HR',
    object_name     => 'EMPLOYEES',
    column_name     => 'SALARY',
    policy_name     => 'SALARY_REDACTION',
```

## 安全最佳实践

### 通用

1. **切勿硬编码加密密钥** —— 使用 HashiCorp Vault、HSM 或环境变量
2. **实施密钥轮换** —— 定期轮换密钥（推荐每 90 天）
3. **使用强算法** —— 最低限度使用 AES-256-GCM 或 AES-256-CBC
4. **应用纵深防御** —— 将 TDE 与应用层加密相结合
5. **监控加密状态** —— 定期验证钱包和密钥健康状态
6. **测试灾难恢复** —— 确保在故障后能够解密数据

### TDE 专用

1. 使用强密码保护钱包
2. 使用 HSM 或 Oracle 密钥管理器进行密钥管理
3. 为所有敏感表空间启用加密
4. 定期审计加密与未加密的列
5. 测试钱包恢复程序

### 应用层专用

1. 使用认证加密（AEAD）模式，如 GCM
2. 为每次加密操作生成唯一的 IV/nonce
3. 将加密数据和元数据与密钥分开存储
4. 实施适当的错误处理（切勿在错误时泄露明文）
5. 记录加密操作而不记录敏感数据

### 标签安全专用

1. 定义清晰的标签层次结构和组件
2. 定期审查和更新标签策略
3. 培训应用程序开发人员了解 OLS API 集成
4. 监控标签策略的性能影响
5. 在非生产环境中测试标签强制执行

### 数据脱敏专用

1. 基于用户角色定义清晰的脱敏策略
2. 对高度敏感的数据使用完全脱敏
3. 对显示用途使用部分脱敏（例如，信用卡最后 4 位数字）
4. 使用不同的用户上下文测试脱敏策略
5. 监控脱敏策略的性能影响
